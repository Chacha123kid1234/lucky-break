# Lucky Break

An original first-person browser casino crawler for 1–6 friends. The resort, mascots, cosmetics, patterns, icons, synthesized sound effects and music are generated by this repository. There are no assets from any existing casino videogame. All chips and tickets are fictional; no payments, purchases of chips, prizes, crypto or cash-outs exist.

## Run

Install Node.js 22 or newer, then:

```sh
npm install
npm run dev
```

Open `http://localhost:3000`. For production:

```sh
npm ci --omit=dev
npm start
```

If that port is occupied, set `PORT`. The implementation session used `http://localhost:3100`.

The working title and resort brand are defined once in `shared/config.js` under `BRAND`. Changing them updates the menu, document title, loader and world signage. Hosting service resource names can be renamed separately.

## Play together

Choose Play → Host → one of three save slots → rules → Create Room. Copy the invite from the room menu, or give your friends the six-character code. Your friends join using the same server URL, with the code, or by opening the invite. Solo uses the same authoritative server. Browser profiles use a private bearer token stored locally; clearing browser storage creates a new profile.

Walk to the item stalls, buy an item with shared tickets, and pick up the physical purchase. Choose a daily dare at the broker. Board the pink party shuttle; a majority of connected teammates (or everyone under the chosen rules) must be ready. Explore the casino, use E at a physical terminal, and gamble with the shared bank. Finish the quota before time runs out. The shift keeps running after quota clearance unless automatic ending was selected. Results require a continue vote. Twelve days cover four tiers and lead to a final decision; endless saves keep scaling.

WASD move, mouse look, Shift sprint, Space jump, C crouch, E interact/pick up, F use/throw, G drop, Q ping, Tab players, T/Enter chat, V voice push-to-talk, B emotes, Escape menu. Click the world to capture the mouse. Settings include key rebinding, graphics presets, FOV, resolution, bloom, shadows, camera bob, reduced motion, high contrast and individual volumes.

Every terminal accepts physical-looking keypad controls or number keys, plus MIN / percentages / MAX. The ordinary limit is half of the available shared bank. Volt Wand unlocks an all-in temporarily; Sun Chip protects one stake. Hit/stand/double, cash-outs, tile picks, poker holds and nudges are validated on the server. Teammates see the rounds on the in-world machine.

## Systems

- Express + Socket.IO server, ES module Three.js client, WebGL, Pointer Lock, Web Audio and WebRTC.
- Server-owned rooms, 20 Hz snapshots, authoritative input simulation, prediction/correction, interpolation and short dead reckoning. Interactions use a capped 200 ms position history.
- Seventeen game engines: blackjack, European roulette with multiple bets, additive 3×3 reels, street craps, fortune wheel, duck derby, money wheel, penguin crossing, keno, rocket crash, HiLo, Plinko, dragon tower, minefield, solo poker, baccarat and original Coin Cascade.
- BigInt bank, fixed-point payouts, serialized mutations, replay-resistant action IDs. The client never submits payout amounts or outcomes.
- Seeded day layouts, independent shops/challenges/game streams; future RNG and hidden cards never enter public snapshots.
- Fifteen items/upgrades, physical purchases, one held object, body exchange/restoration, daily dares, rotating cosmetics, original cosmetic geometry, emotes, voice, chat, pings and persisted achievements/statistics.
- Shift snapshots every three seconds and event projections. Rewind restores the projection at up to sixty seconds ago, moves active timers, removes later events and permanently burns the used remote's unique ID.
- Atomic JSON saves through temporary-file write, fsync and rename. Rooms checkpoint every fifteen seconds and on relevant actions. A process restart refunds unsettled reserved stakes once and resumes in a safe hub; an ordinary browser refresh restores the live room exactly.

The first three floors retain their distinct machine pools. The penthouse includes every type in randomized sockets. Each shift changes assignments and orientations while keeping fixed architecture and navigation.

## Validation

```sh
npm test
npm run check
npm run test:load
npm run test:http
npm run test:browser
```

`npm test` covers payouts, all game completion paths, bank atomicity, idempotent settlement, challenges, physical purchases, item effects, microphone activity gating, rewind, large-number quotas, saves, reconnects, capacity/security checks, collision/throws/basket scoring, transitions, a shortened twelve-day campaign, all endings, eighteen endless days, and UI/mesh construction. Campaign tests advance the clock/bank deliberately; they do not claim to be full-length playtests. Mesh/UI tests use a mock 2D canvas and do not validate rendered WebGL pixels.

`test:load` passed with six actual Socket.IO clients. It rejects a seventh, walks using normal authoritative inputs, purchases/picks up an item, repeats a request ID, reconnects, boards the shuttle, plays blackjack and roulette simultaneously, completes a shared dare, compares timed results/ticket awards, returns through the shuttle and verifies a refreshed client's next-day bank/tickets/item. It uses relaxed custom rules and a real 60-second shift. Bots exist only in this test file and are never displayed as real players in the product. Set `TEST_URL` to change the target (default `http://localhost:3100`).

`test:browser` uses Playwright with installed Chrome, two separate browser contexts and screenshots in `test-results`. It exercises hosting/joining, remote avatars, purchases, carried items, transport, shared layout, simultaneous blackjack/roulette, shared dare rewards, timed results, return and both browser refreshes. Run the server with `DEV_ADMIN=1` outside production for test inspection. Set `TEST_FAST_CAMPAIGN=1` to additionally exercise all twelve days/finale using explicit development clock/bank commands and launch a separate endless save; this acceleration is not a full-length campaign playtest. `BROWSER_CDP` can target an already running authorized automation browser. Browser launch was blocked by the implementation environment's approval policy, so these browser checks and desktop GPU performance remain unverified. The project must not be described as having passed the user's full browser acceptance test until that test has actually run.

## Production hosting

Use one persistent Node instance with WebSockets enabled. Rooms are in memory and saves are on disk; multiple replicas would require a shared room service/adapter and storage. Keep `NODE_ENV=production` and `DEV_ADMIN=0`.

- **Railway:** Dockerfile plus `railway.toml`. Attach a volume at `/app/data`. Set `PUBLIC_ORIGIN` to your HTTPS origin.
- **Render:** `render.yaml` includes a persistent disk at `/var/data`; a plan supporting persistent disks is required.
- **Fly.io:** use a unique app name in `fly.toml`; create the `lucky_break_data` volume in your chosen region before deploying. Run one machine.
- **VPS/ordinary Node hosting:** reverse proxy HTTPS to the Node port; proxy Socket.IO upgrades and use a persistent `DATA_DIR`. Docker: `docker build -t lucky-break .`, then `docker run -p 3000:3000 -v lucky-break-data:/app/data lucky-break`.

HTTPS or localhost is required for microphone permission. Voice uses a WebRTC mesh with distance gain and stereo pan. Public STUN is configured; set `TURN_URL`, `TURN_USERNAME` and `TURN_CREDENTIAL` for networks that require relaying. Those credentials are intentionally passed to browsers: use appropriately scoped, short-lived credentials. Voice permission/network failures fall back to text chat. Microphone RMS activity is sent as a speaking boolean; speech is never analyzed by server game logic.

Back up `data/store.json`. Do not serve `data/` publicly. The server does not expose it as a static directory. A browser profile's local token is its credential; sharing browser storage shares the profile. No external account system is used.

## Development

Copy `.env.example` to `.env` and set `DEV_ADMIN=1`, with `NODE_ENV` outside production, to open the backtick console. Only the original room owner can run commands:

```text
help
money 100000
tickets 50
day 8
floor 3
quota complete
spawn rewind
teleport hub
teleport floor1
timer 30
unlockall
healbody
challenge complete
endday
rng custom-seed
```

Copy is centralized in `client/lang/en.js`. The locale loader provides English fallback and accepts additional locale modules for French, German, Spanish, Italian, Portuguese, Polish, Turkish, Ukrainian, Russian, Japanese, Korean and Simplified Chinese. These translations are not supplied.

The visuals and sound are fully procedural. Their final artistic quality, sustained 60 FPS target, accessibility usability and full-length campaign balance still need browser/manual playtesting. This is a working implementation with testable systems, not a claim of verified commercial-release polish.
